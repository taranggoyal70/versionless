# Domain documentation

Before exploring the codebase, read `CONTEXT.md` and any relevant ADR in `docs/adr/`.

Use the glossary terms from `CONTEXT.md` in code, tests, issues, and product copy. If a proposed change contradicts an ADR, surface the conflict before implementing it.

This is a single-context repository. If it later becomes multi-context, add a root `CONTEXT-MAP.md` and context-specific `CONTEXT.md` files.
